# Контент Фабрика

Инструмент для генерации, редактирования и автоматической публикации постов в VK и Telegram на базе многоагентного AI-конвейера.

Разработан для двух каналов:
- **[Я-Инженер](https://vk.com/club238494545)** (ВКонтакте) и **[@i_am_an_engineer1](https://t.me/i_am_an_engineer1)** (Telegram)
- **Безопасность всегда** (ВКонтакте, отдельная группа) и соответствующий Telegram-канал

---

## Возможности

### Генерация контента
- Ввод темы в свободной форме — AI сам найдёт актуальные источники и напишет пост
- Пятиступенчатый агентный конвейер: Контролёр → Автор → Редактор → Критик → Финальный редактор
- Первый агент использует веб-поиск в реальном времени (`gpt-4o-search-preview`)
- AI рекомендует оптимальный день недели публикации под тематику поста
- Корректировка готового поста через чат без потери контекста

### Канал «Безопасность всегда» — расширенный конвейер
- Шестой агент **Иллюстратор** формирует текстовое описание изображения к посту
- Отдельный генератор тем с собственным планом публикаций (`/api/bez-plan`)
- Генерация иллюстраций через `gpt-image-2` (endpoint `POST /api/openai/generate-image`) — реализована, в UI временно отключена
- При публикации иллюстрация загружается в VK через `photos.getWallUploadServer` → `photos.saveWallPhoto` → `wall.post` с вложением
- URL иллюстрации сохраняется в БД (`illustration_url`) вместе с постом

### Автоматический режим (Автомат и Автопилот)
- Кнопка **«Автомат»** — одним нажатием генерирует готовый пост из свежих источников без ввода темы
- **Дедупликация источников** — система запоминает использованные материалы (SHA1-хэш) и не повторяет их; при исчерпании сбрасывает список автоматически
- **Автопилот Я-Инженер** — ежедневный автозапуск в **12:00 МСК**: если на сегодня нет поста — генерирует и сразу публикует
- **Автопилот Безопасность** — ежедневный автозапуск в **10:00 МСК** по той же логике
- Оба автопилота не создают дублей: если публикация на сегодня уже есть — пропускают

### Расписание публикаций
- Автоматическая публикация по расписанию в **12:00 МСК** — одновременно в VK и Telegram
- Кнопка «Опубликовать немедленно» — мгновенная отправка в оба канала без ожидания
- Кнопка «В публикацию» — ставит пост на ближайший свободный выбранный день недели
- Визуальный календарь с отображением запланированных публикаций

### Библиотека постов
- Хранение черновиков, запланированных и отклонённых постов
- Встроенный редактор: изменить текст, перепланировать или немедленно опубликовать
- Поиск по тексту и заголовкам

### Архив
- Все опубликованные посты с точным временем публикации
- Прямые ссылки на посты в VK и Telegram
- Бейдж с темой дня
- Счётчик символов каждого поста

## Логика публикации по каналам

При каждой публикации (плановой или немедленной) пост отправляется **одновременно в VK и Telegram**:

| Сценарий | Поведение |
|----------|-----------|
| Оба канала доступны | Пост уходит в VK и Telegram |
| VK недоступен (немедленная публикация) | Операция прерывается с ошибкой |
| Telegram недоступен | Пост всё равно уходит в VK, ошибка пишется в лог |
| VK недоступен (плановая публикация) | Пост уходит в Telegram, ошибка в лог |
| Загрузка иллюстрации в VK не удалась | Пост публикуется текстом, предупреждение в лог |

## Переменные окружения

| Переменная              | Описание                                                                  |
|-------------------------|---------------------------------------------------------------------------|
| `DATABASE_URL`          | Строка подключения к PostgreSQL                                           |
| `PROXYAPI_KEY`          | Ключ ProxyAPI для доступа к GPT-4o, gpt-4o-search-preview, gpt-image-2   |
| `VK_ACCESS_TOKEN`       | Group-токен VK для канала Я-Инженер                                       |
| `VK_GROUP_ID`           | ID группы Я-Инженер (`club238494545` или `238494545`)                     |
| `VK2_ACCESS_TOKEN`      | Group-токен VK для канала Безопасность всегда                             |
| `VK2_GROUP_ID`          | ID группы Безопасность всегда                                             |
| `VK_USER_TOKEN`         | **Личный** токен VK с правами `photos,wall,offline` — нужен для загрузки иллюстраций (group-токены не имеют доступа к `photos.*`) |
| `SESSION_SECRET`        | Секрет для сессий Express                                                 |
| `TELEGRAM_BOT_TOKEN`    | Токен Telegram-бота (@my_telegram532_bot «Толик-админ»)                   |
| `TELEGRAM_CHANNEL_ID`   | ID/username канала Telegram для Я-Инженер (например `@i_am_an_engineer1`) |

### Как получить VK_USER_TOKEN

1. Создай Standalone-приложение VK: https://vk.com/editapp?act=create (тип «Standalone»)
2. Скопируй **ID приложения** из настроек
3. Открой в браузере:
   ```
   https://oauth.vk.com/authorize?client_id=ВАШ_ID&display=page&redirect_uri=https://oauth.vk.com/blank.html&scope=photos,wall,offline&response_type=token&v=5.131
   ```
4. После авторизации скопируй `access_token` из URL-строки (до `&expires_in`)

> Токены с vkhost.github.io привязаны к IP браузера и не работают с сервера — нужно именно Standalone-приложение.

## Деплой на VPS через Docker

### Требования
- Docker + Docker Compose v2
- VPS: 1 vCPU, 1 ГБ RAM, 20 ГБ SSD (Ubuntu 22.04 LTS)

### Шаги

**1. Склонировать репозиторий на сервер:**
```bash
git clone https://github.com/andrew11morozovtwo/content-factory.git
cd content-factory
```

**2. Создать файл с переменными окружения:**
```bash
cp .env.example .env
nano .env   # заполнить реальными значениями
```

**3. Собрать и запустить:**
```bash
docker compose up -d --build
```

При первом запуске автоматически:
- Создастся база данных PostgreSQL
- Применится схема (drizzle push)
- Запустится API-сервер и фронтенд

**4. Проверить:**
```bash
docker compose ps        # все сервисы должны быть Up
docker compose logs api  # логи API
```

Приложение доступно по адресу `http://IP_СЕРВЕРА`

### Обновление
```bash
git pull
docker compose up -d --build
```

### Структура Docker-контейнеров

| Контейнер | Роль |
|-----------|------|
| `db`  | PostgreSQL 16 (данные сохраняются в volume) |
| `api` | Node.js API-сервер (порт 3000 внутри сети) |

## Стек

- **Монорепо:** pnpm workspaces, Node.js 24, TypeScript 5.9
- **API:** Express 5, Drizzle ORM, PostgreSQL, Zod v4
- **Фронтенд:** React 19, Vite, wouter, shadcn/ui, Tailwind CSS
- **AI:** GPT-4o (генерация) + GPT-4o-search-preview (веб-поиск) + gpt-image-2 (иллюстрации), через ProxyAPI
- **Публикация:** VK API v5.131 (`wall.post`, `photos.*`) + Telegram Bot API (`sendMessage`)
- **Кодогенерация:** Orval (React Query хуки + Zod-схемы из OpenAPI)

## Ключевые архитектурные решения

- **Contract-first API:** OpenAPI YAML → Orval codegen → React Query хуки + Zod-схемы. Fetch-вызовы на фронтенде вручную не пишутся.
- **VK и Telegram публикуются независимо:** сбой одного канала не блокирует другой (кроме VK при немедленной публикации).
- **Иллюстрации требуют личного токена:** VK group-токены не имеют доступа к `photos.*` (ошибка 27). Загрузка всегда идёт через `VK_USER_TOKEN`.
- **Большие payload-ы:** лимит `express.json` увеличен до 20 МБ, чтобы base64-иллюстрации (~5 МБ) проходили при создании поста. URL иллюстрации хранится в БД (`illustration_url`) и не передаётся в теле запроса на публикацию.
- **Запланированный паблишер** опрашивает БД каждые 60 секунд; запускается немедленно при старте сервера.
